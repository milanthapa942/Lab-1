# Lab 1: Design, Assembly, and Engineering Notebook

**Session date:** September 7, 2026

## Lab Tasks

1. Follow the session instructions and finalize a design for a 3D card or object. Possible materials include wood, 3D-printed parts, cardboard, paper, and plastic parts. For inspiration, see the [layered cardboard sculpture tutorial](https://www.instructables.com/How-to-Make-a-Layered-Cardboard-Sculpture-of-Almos/).
2. Assemble **at least three cards or objects** and measure the assembly time for each. One student can assemble while another records the time. These measurements will provide a baseline for comparison with a future robotic solution.
3. Document the design and assembly process in the engineering notebook. Include a timing table and calculate the **minimum, maximum, and mean** assembly times.
4. Resolve any questions about Git and GitHub, and complete the quiz in Learn if it is still unfinished.
5. Clone the [lab repository](https://github.com/ICT-Robotics26/lab1) and create a new branch.
6. Copy the contents of the `99` template folder into a new folder named with your lecturer-assigned group number.
7. Have one team member commit the documentation, push the branch, and open a pull request.
8. Have another team member review the documentation and merge the pull request.

## Engineering Notebook Requirements

The engineering notebook is a chronological record of the team's design work. Write it in **Markdown**, host it on the [ICT-Robotics GitHub](https://github.com/ICT-Robotics26), and share it among team members.

Include:

- **Title page:** Group number, optional group name, and team members.
- **Table of contents:** Use Markdown headings so it can be generated automatically; no manual contents list is needed.
- **Dated entries:** Use a main heading in `YYYY-MM-DD` format for each session and list who was present and working.
- **Work details:** Describe the design, materials, assembly steps, and results in enough detail for someone else to reproduce the work. Add diagrams, data, code, photos, and explanations where useful.
- **Reflection:** Record successes, failures, future needs, and remaining tasks.
- **References:** Cite the manuals, books, websites, and other sources used.

## Writing and Review Responsibilities

Write notes **during every laboratory session**, as the repository history will be checked. Do not wait until the end of the project to document the work.

During the eight-week course, **each team member** must:

- Complete at least **two commit, push, and pull request contributions on different days**.
- Review and merge at least **two pull requests from other team members on different days**.

These contributions affect the grade and will be checked through the repository history. Assign a writer and a different reviewer for each session, rotating the roles so everyone meets the requirements.

## Good Notebook Practices

- Write clearly in complete sentences so others, including new team members, can understand the work.
- Record work and observations as they happen.
- Keep entries in chronological order, with a separate dated heading for each day.
- Include enough detail to reproduce the process.
- Explain figures and sketches in the text.
